# API Reference

Full interactive docs are auto-generated by FastAPI at `/docs` (Swagger UI)
and `/redoc` once the app is running. This file is a quick reference for
what exists and why.

## Health

`GET /health` — liveness/readiness check, no auth. Used by Docker/k8s
health probes.

## B2B — merchant accounting & credit

| Endpoint | Purpose |
|---|---|
| `POST /b2b/merchants` | Register a merchant |
| `POST /b2b/entries/text` | Post a ledger entry directly (skips voice/vision, still runs guardrails) |
| `POST /b2b/entries/voice` | Upload a voice note (multipart: `merchant_id`, `transaction_kind`, `audio`) |
| `POST /b2b/entries/photo` | Upload a bill photo (multipart: `merchant_id`, `transaction_kind`, `gst_rate`, `photo`) |
| `POST /b2b/approvals/{id}/decide` | Approve/reject a paused action (`?approve=true`) |
| `GET /b2b/merchants/{id}/loan-readiness` | Pre-screen score before an OCEN submission |

`entries/voice` and `entries/photo` both return either:
```json
{"status": "posted", "transaction_group": "<uuid>"}
```
or, when the guardrail agent flags something:
```json
{"status": "needs_human_approval", "approval_request_id": "<uuid>", "reasons": ["..."]}
```

## B2C — WhatsApp ordering

| Endpoint | Purpose |
|---|---|
| `POST /b2c/merchants/{merchant_id}/orders` | Submit a parsed WhatsApp order (used internally by the webhook handler, or directly for testing) |

Request body:
```json
{"from_number": "+91XXXXXXXXXX", "message_text": "Send 5 bags of sugar and 2 cartons of soap by 4 PM"}
```

Response:
```json
{
  "order_id": "<uuid>",
  "status": "confirmed",
  "total_amount": 270.0,
  "upi_link": "upi://pay?pa=...",
  "parse_confidence": "high"
}
```

## Webhooks

| Endpoint | Purpose |
|---|---|
| `GET /webhooks/whatsapp` | Meta's one-time webhook verification handshake |
| `POST /webhooks/whatsapp` | Inbound WhatsApp messages (signature-checked) |
| `POST /webhooks/payments/psp` | Your PSP's payment-status callback |

## Error shape

Standard FastAPI/Pydantic validation errors (422) and explicit `HTTPException`
raises (404 for missing merchants/orders, 401 for bad webhook signatures).
Integration failures inside agent graphs are caught and surfaced as
`needs_human_approval` responses rather than 500s, wherever a human queue
makes sense; anything unexpected still surfaces as a 500 — check logs.
